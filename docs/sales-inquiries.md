# 销售型独立站 · 2026-09-14

网站围绕采购转化设计：客户浏览或搜索款式，收集多个产品与数量，再留下联系渠道和采购要求。也可直接提交 OEM 需求或请求选款建议，无需线上付款。

## 客户的使用流程

1. 首页选择“Pilih Produk”浏览目录，或“Ajukan Kebutuhan”直接填写需求。
2. 可点产品的“Minta Harga Grosir”询问单款，也可用“Simpan pilihan”积累多款。
3. 填写联系人、WhatsApp 或邮箱、城市；可补充业务类型、公司、数量、时间和备注。OEM 需说明项目要求。
4. 同意数据用于跟进并提交，看到编号才代表网站确认保存。若未确认，可保留原内容重试。
5. 可选用带编号与采购摘要的 WhatsApp 链接继续沟通。网站不会代客户发送 WhatsApp 消息。

## 销售人员的使用流程

进入网站 `/sales`，使用获得授权的管理账号登录。当前配置为网站拥有者账号。

- 查看新需求和客户留下的联系方式；展开卡片看多款数量、采购 / OEM 说明和目标时间。
- 点击联系渠道进入 WhatsApp 或邮件工具，确认内容后由销售自行发送。
- 将状态改为“已联系”“已报价”或“完成”，填写内部备注并保存。
- 状态计数与筛选可用于安排跟进；每页最多显示 50 条。点击“重新加载”获取新询盘。
- 当前不发送自动邮件通知。需销售人员定期查看后台；状态“已报价”由销售手动记录，不会触发发送报价。

## 已实现的保护与验证

- 客户资料在 D1 持久保存；浏览器本地存储只记款式 ID 和数量。
- 服务端核验联系格式、合法款式、整数数量、长度及同意状态，拒绝跨站写入。
- 同一请求重复发送返回相同编号；内容不同却复用请求编号则拒绝，避免混淆。
- 未获授权的访客无法读取或修改询盘。生产平台负责注入身份，服务端核验管理账号名单。
- 后台用记录版本号防止两个窗口相互覆盖跟进备注；冲突时提示重新加载，当前编辑不会误报成功。
- 本地验证覆盖数据库保存、响应丢失后重试、并发重复请求、权限隔离、更新后刷新、筛选，以及 15 种前台尺寸、4 种后台尺寸。
- 新增后台与数据库模块的静态检查通过。项目已有 UI 模板的全量检查仍有原生图片、组件标签识别等既存规则报错；类型检查及功能、布局测试通过。

## 配置与交付

`.openai/hosting.json` 声明 `DB`，数据库结构位于 `db/schema.ts`，迁移保留在 `drizzle/`。不在请求运行时创建表，也不把本地测试记录随网站发布。

管理允许名单通过 Sites 的 `SALES_ADMIN_EMAILS` 环境变量配置，多个邮箱以逗号分隔。拥有网站访问资格并不自动获得销售后台权限。源码包不含生产配置值，换到新站点需重新设置允许名单和数据库绑定。

网站仍沿用现有私密访问范围及 noindex。正式对外获客时，需要另行开放前台访问；销售后台仍须保留账号限制。

客户如需更正或删除资料，可通过隐私页的业务邮箱联系团队并提供询盘编号。当前不提供访客自助查询链接，避免联系资料外泄。
