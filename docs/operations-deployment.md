# LOONG JUMP 运营工作台与部署说明

本次面向现有 `loongjump.com` 自托管 Node / Docker 运行方式，新增入口 `/manage/`。公开网站和原 `/sales` 询盘后台保留；询盘继续存储于原 SQLite 数据库。后台使用中文，客户侧继续使用印尼语。

## 对应功能与边界

| 建议 | 本次实现 | 使用条件 / 边界 |
|---|---|---|
| 2.1 团队协作 | 所有者、经理、销售、运营、分析五种角色；账号新增、停用、重设密码；公共池、负责人分配、轮流自动分配；操作记录 | 在团队管理中创建真实员工，勾选参与自动接单。没有符合条件的成员时进入公共池。仅新询盘自动轮流分配，历史公共池由经理分配 |
| 2.2 日常运营 | 产品、新闻、图片、MP4、活动 Banner；上传媒体；草稿/发布/下架；开始/结束时间；内容分配 | 单文件 12 MB；大视频可填 HTTPS 地址；有旁白的视频请提供 VTT 字幕。正文按纯文本渲染，不接受脚本或 HTML |
| 2.3 询盘管理 | 网站询盘自动入库；邮件、WhatsApp、电话、展会线索人工录入；状态、备注、沟通记录；邮件/WhatsApp 回复草稿入口 | 邮箱和 WhatsApp 的自动收件、服务器代发消息尚未接通；打开对应应用后由销售实际发送，保存沟通记录不代表发送 |
| 2.4 手机管理 | 响应式工作台、PWA 安装清单、主屏幕图标、离线说明 | 使用手机浏览器“添加到主屏幕”；需联网，不缓存客户资料；不是上架应用商店的原生 APP，无推送通知 |
| 2.5 动态运营 | 真实浏览、会话、询盘、内容状态；总览和分析每 30 秒刷新 | 编辑表单不会被自动刷新覆盖，列表可手动刷新 |
| 3.1–3.3 智能洽谈 | WhatsApp、邮件、询盘表单、可选 AI 文本客服；气泡、面板、简洁三种样式 | AI 需要服务器密钥、模型和后台开关全部启用；未配置时提供人工渠道；没有实时语音视频通话 |
| 3.4 自定义询盘框 | 标题、引导语、最多 6 个自定义文本字段及必填校验 | 基础联系人、联系方式、隐私同意和采购校验保留；字段由服务端验证 |
| 3.5 多产品询价 | 现有选型清单继续使用，新增/编辑的后台产品也支持多款与数量询价 | 下架和未到展示时间的产品不能加入新的有效询盘；已保存询盘保留提交时的产品快照 |
| 4.1 全球流量 | 访问明细、按日趋势、页面、来源、终端、会话和跳出率 | 访客同意后采集，尊重 DNT/GPC；当前未接入 GeoIP，因此流量国家显示“未获取”，不会用浏览器语言猜测国家 |
| 4.2 询盘分析 | 来源、客户填写的国家/地区、趋势、终端；授权访客的来源关联 | 来源跟踪受访客同意和浏览器存储限制；外部渠道由员工录入，历史数据缺失字段保留“未获取” |
| 4.3 搜索分析 | Google/Bing/其他搜索报表 CSV 导入；点击、展示、CTR、平均排名及日期 | 尚未接入搜索引擎账号自动同步；只分析真实导入数据，不模拟搜索排名 |
| 4.4 运营测评 | 公共池、24 小时未跟进、访问参与度和新闻更新的规则建议 | 这是可解释的规则评估；不是完整技术 SEO 爬虫或搜索引擎官方评分 |

## 权限

- 所有者：全部管理能力。经理不能创建、修改或停用所有者/经理账号。
- 经理：团队日常管理、全部询盘和内容的分配、配置、分析。
- 销售：只读写分配给自己的询盘，可录入归属自己的外部线索；不能读取别人的联系人或公共池详情。
- 运营：只编辑分配给自己的内容，可新建归属自己的内容和上传素材；不读客户资料。
- 分析：只查看汇总分析、非个人访问明细和搜索报表，不读询盘联系人。

身份只来自服务器会话，客户端提供的身份头会被丢弃。角色更改会撤销该成员会话；停用或改为非销售角色的成员，其询盘回到公共池。内容同理解除不再具备编辑权限的负责人。不能停用自身或移除最后一位有效所有者。

首次升级将 `SALES_ADMIN_EMAILS` 中的既有本地账号设为所有者；其他历史 CLI 账号默认停用，等待经理授予权限。不要为新销售简单添加到原环境变量允许名单，应从新后台建账。

## 数据与迁移

- `drizzle/0001_operations.sql` 增加角色、内容、分析、搜索、操作记录及询盘扩展列，保留原询盘记录。
- `drizzle/0002_video_captions.sql` 增加视频字幕地址。
- 自托管启动时 `server/storage.mjs` 按 SQL 文件名自动执行未应用的迁移，记录校验和和时间；不能修改已经应用的 SQL 文件。
- 本次运营表、SQLite 触发器与约束由以上手工 SQL 维护。后续运营表变更应追加 SQL 迁移；不要直接对这些表使用旧 `db/schema.ts` 生成的结构覆盖生产库。
- `website_data` 数据卷保存 SQLite 和 `media/`；上传素材名称为随机 UUID，不接受 SVG/HTML/可执行文件。
- 原始访问事件在服务启动和日常维护时清理至最近 180 天；询盘、内容、搜索报表和操作记录不随访问保留期删除。
- 用户授权统计后才生成访问会话，库中只保存会话 ID 哈希、页面路径、引用域名、终端与时间，不保存原始 IP、完整来源查询参数或询盘正文到访问事件。
- 展示/统计使用 UTC 日界；编辑展示时间时输入的是操作者设备的本地时间。

## AI 配置

在服务器 `/opt/loongjump-website/.env` 设置以下变量，文件不进入仓库：

```dotenv
OPENAI_API_KEY=你的服务端密钥
LOONGJUMP_AI_MODEL=你账号可用的文本模型名称
LOONGJUMP_AI_DAILY_LIMIT=200
```

随后在服务器运行 `docker compose up -d`，进入“客服与表单”启用 AI。模型不硬编码，避免擅自选用超出预算的模型。系统按每日最多调用次数和单次输出 token 数限制使用；这不是金额预算，仍应在 API 平台设置账单限制。当前代理环境中的客户端限速使用连接来源，因此可能由同一代理后的访客共同分摊，属于保守保护。

实现采用 [OpenAI Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses)，`store:false`，只传公开公司/产品资料、用户同意后提交的问题和最多 6 条上下文。模型没有工具、管理权限或客户数据库访问能力；不能下单、发送消息或承诺报价。网站数据库不保存 AI 聊天记录；提供方的数据处理政策仍然适用。

## 搜索报表

从 Google Search Console / Bing Webmaster 导出 CSV，在“搜索表现”选择引擎和报表日期后导入。支持 `query / Top queries / Query`、`clicks`、`impressions`、`position` 及页面/日期的常见表头；支持带引号、逗号和换行的 CSV。一次 1–500 行、文件最大 100 KB。相同引擎、日期、关键词、页面会更新记录。

建议按单日导出。区间报表没有日期列时，应明确选择报表日期，不应当作每日排名。页面只展示最新 300 条记录并按当前显示数据汇总。自动同步与访客 GeoIP 国家识别属于仍待接入的外部数据能力。

## 发布与回退

GitHub Actions 对 PR 和 main 执行类型检查、基础询盘检查、运营服务测试与生产构建；仅 push 到 main 才部署。沿用现有 `SSH_DEPLOY_KEY` 和已有服务器，不修改 DNS。

部署流程：

1. 上传源码到 `app.new` 并构建新镜像，构建期间旧容器继续服务。
2. 将旧镜像标记为 `loongjump-website:rollback-时间戳`，保存旧 compose 和源码。
3. 在 `/backups/predeploy-时间戳` 建立升级前数据库快照；新版备份通过 `VACUUM INTO` 保持一致性并验证完整性，也复制不可变媒体目录。首次升级使用上一版本的备份命令。
4. 切换新源码和镜像，启动容器，等待健康检查。
5. 验证公网首页、公开内容接口、PWA manifest。失败则恢复旧镜像、旧源码和 compose。

回退不会自动把数据库恢复到旧快照，因为这可能丢掉部署期间的新询盘；本次迁移是向后兼容的追加迁移。预备份、失败源码、旧镜像保留供人工核查，需按实际磁盘容量定期清理。日常数据库备份默认保留 30 天；媒体备份目录共享保留，以保证历史内容可恢复。

恢复数据库时需先停服务，将当前数据库另存，再执行已有 `server/cli.mjs restore`；媒体需同步恢复备份中的 `media/`。不应对运行中的生产数据直接覆盖。

## 本地验证

运行时需要 Node.js 24（与 Docker 一致），不能只用最低 22.13 运行新增的原生 TypeScript 导入。命令：

```bash
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
node scripts/check-inquiries.mjs
node scripts/check-operations.mjs
pnpm build:server
```

按 README 自托管模式启动本机实例，再通过指定本机地址运行 HTTP 集成检查（只允许 localhost / 127.0.0.1，会创建明确标注的临时数据，不能对生产执行）：

```bash
QA_URL=http://localhost:3187 QA_EMAIL=preview@example.test \
QA_PASSWORD_FILE=/安全的本机测试密码文件 node scripts/check-operations-http.mjs
```

测试不发送邮件或 WhatsApp，不调用真实付费 AI。AI 使用 mock 响应验证接口、密钥缺失、用户同意和限额逻辑。上线后还需在配置真实 AI 凭据后做授权业务验收。
